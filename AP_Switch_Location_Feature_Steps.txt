WHAT THIS FEATURE DOES
----------------------
1. The system scans all nearby APs and ranks them by quality score.
2. The dashboard shows a "Switch to this AP" button next to every better AP.
3. The user clicks the button for the AP they want.
4. The system runs the OS command to disconnect from the current AP
   and reconnect to the chosen one — automatically.
5. While the user is still connected to a bad AP, the system shows
   EXACT movement directions in plain English, for example:

       "Move LEFT approximately 8 m towards AP-Lab-North (BSSID: AA:BB:CC:DD:EE:02).
        Signal will improve from -78 dBm to approximately -58 dBm."

6. As the user walks, the RSSI changes in real time. The direction
   instruction updates every scan cycle (every 10 seconds) until the
   user reaches the AP or switches.

This feature upgrades your project from PASSIVE monitoring to
ACTIVE ASSISTANCE — a significant engineering contribution.

PART A — AP SWITCHING (THE RECONNECT FEATURE)

HOW OS-LEVEL WIFI SWITCHING WORKS
-----------------------------------
Operating systems expose command-line tools to manage WiFi profiles.
Your app calls these commands as a subprocess — exactly like the scanner.py
already does for scanning. No extra hardware. No admin access to the APs.

Windows uses:   netsh wlan
Linux uses:     nmcli  (NetworkManager command-line interface)

The process on both platforms is:
  Step 1 — Disconnect from the current AP.
  Step 2 — Connect to the target AP by its SSID (and BSSID if possible).

The user must have previously connected to the target AP at least once,
OR the network must be open / use a known password already saved.
For a university Eduroam network, the device usually already has
saved credentials, so switching works without re-entering a password.

import subprocess
import platform
import time
import config


def switch_ap_windows(target_ssid: str, target_bssid: str = None) -> dict:
    """
    Disconnect from current AP and reconnect to target_ssid on Windows.

    Uses: netsh wlan disconnect
          netsh wlan connect name="<SSID>"

    Returns a dict:
        { "success": True/False, "message": "...", "time_taken_s": float }
    """
    start = time.time()

    # Step 1: Disconnect
    try:
        result = subprocess.run(
            ["netsh", "wlan", "disconnect"],
            capture_output=True, text=True, timeout=10
        )
        if "disconnected" not in result.stdout.lower() and result.returncode != 0:
            return {
                "success": False,
                "message": f"Disconnect failed: {result.stdout.strip()}",
                "time_taken_s": 0
            }
    except Exception as e:
        return {"success": False, "message": f"Disconnect error: {e}", "time_taken_s": 0}

    # Wait briefly for OS to process disconnect
    time.sleep(1.5)

    # Step 2: Connect to target SSID
    try:
        result = subprocess.run(
            ["netsh", "wlan", "connect", f'name="{target_ssid}"'],
            capture_output=True, text=True, timeout=20
        )
        elapsed = round(time.time() - start, 2)

        if result.returncode == 0:
            return {
                "success": True,
                "message": f"Successfully connected to {target_ssid}.",
                "time_taken_s": elapsed
            }
        else:
            return {
                "success": False,
                "message": f"Connect failed: {result.stdout.strip()}",
                "time_taken_s": elapsed
            }
    except Exception as e:
        return {"success": False, "message": f"Connect error: {e}", "time_taken_s": 0}


def switch_ap_linux(target_ssid: str, target_bssid: str = None) -> dict:
    """
    Disconnect and reconnect on Linux using nmcli.

    Uses: nmcli device disconnect wlan0
          nmcli device wifi connect "<SSID>"   [bssid <BSSID>]

    IMPORTANT: On Linux you may need to run as sudo, or grant the user
    permission via polkit. Test first with:
        nmcli device wifi list
    If that works without sudo, switching will also work.
    """
    start = time.time()

    # Step 1: Disconnect
    try:
        subprocess.run(
            ["nmcli", "device", "disconnect", "wlan0"],
            capture_output=True, text=True, timeout=10
        )
    except Exception as e:
        return {"success": False, "message": f"Disconnect error: {e}", "time_taken_s": 0}

    time.sleep(1.5)

    # Step 2: Connect — use BSSID if provided (more precise)
    try:
        if target_bssid:
            cmd = ["nmcli", "device", "wifi", "connect", target_ssid,
                   "bssid", target_bssid]
        else:
            cmd = ["nmcli", "device", "wifi", "connect", target_ssid]

        result = subprocess.run(cmd, capture_output=True, text=True, timeout=30)
        elapsed = round(time.time() - start, 2)

        if result.returncode == 0:
            return {
                "success": True,
                "message": f"Successfully connected to {target_ssid}.",
                "time_taken_s": elapsed
            }
        else:
            return {
                "success": False,
                "message": f"Connect failed: {result.stderr.strip()}",
                "time_taken_s": elapsed
            }
    except Exception as e:
        return {"success": False, "message": f"Connect error: {e}", "time_taken_s": 0}


def switch_to_ap(target_ssid: str, target_bssid: str = None) -> dict:
    """
    Main switching function — platform-aware.
    Call this from app.py when the user clicks the Switch button.
    """
    os_name = platform.system()
    print(f"[Switcher] Switching to: {target_ssid} ({target_bssid or 'any BSSID'})")

    if os_name == "Windows":
        return switch_ap_windows(target_ssid, target_bssid)
    elif os_name == "Linux":
        return switch_ap_linux(target_ssid, target_bssid)
    else:
        return {
            "success": False,
            "message": "Switching not supported on this OS.",
            "time_taken_s": 0
        }

PART B — EXACT LOCATION GUIDANCE (THE NAVIGATION FEATURE)
================================================================================

THE CORE IDEA
--------------
WiFi RSSI (signal strength) changes as you physically move.
When you move TOWARDS an AP, RSSI gets stronger (less negative).
When you move AWAY, RSSI gets weaker (more negative).

The system cannot use GPS inside a building because GPS does not work indoors.
Instead, it uses RSSI-based triangulation + the rate of RSSI change
as you walk to estimate your direction and distance to the target AP.

This is called RSS-based indoor localisation — it is a real engineering
technique used in commercial indoor navigation systems. Your supervisor
will recognise it as academically valid.


HOW RSSI MAPS TO DISTANCE — THE LOG-DISTANCE PATH LOSS MODEL
--------------------------------------------------------------
This is the engineering formula that converts RSSI to distance.

    RSSI(d) = RSSI_0 - 10 * n * log10(d)

Where:
    RSSI(d)  = signal strength at distance d (dBm) — what you measure
    RSSI_0   = signal strength at 1 metre from the AP (dBm) — calibration value
    n        = path loss exponent (environment constant)
               Typical values:
                   2.0 = free space (no walls)
                   2.5 = open office / lab (some obstacles)
                   3.0 = indoor with multiple walls
               Use n = 2.7 for a typical university lab
    d        = distance in metres — what you want to calculate

Rearranging to solve for d:

    d = 10 ^ ((RSSI_0 - RSSI) / (10 * n))

Example:
    RSSI_0 = -40 dBm  (measured by standing 1m from the AP at setup)
    RSSI   = -70 dBm  (current reading)
    n      = 2.7

    d = 10 ^ ((-40 - (-70)) / (10 * 2.7))
      = 10 ^ (30 / 27)
      = 10 ^ 1.111
      = 12.9 metres

This tells the user: "You are approximately 13 metres from AP-Lab-North."


HOW DIRECTION IS DETERMINED — RSSI DELTA METHOD
-------------------------------------------------
The system cannot know which physical direction the AP is in
without a floor map. However, it CAN tell the user if they are
getting CLOSER or FURTHER using the RSSI change between scans.

    delta_rssi = current_rssi - previous_rssi

    If delta_rssi > +2 dBm  →  "You are moving CLOSER. Keep going."
    If delta_rssi < -2 dBm  →  "You are moving FURTHER AWAY. Turn around."
    If -2 <= delta_rssi <= +2  →  "Signal stable. Try moving left or right."

The ±2 dBm dead zone accounts for normal RSSI measurement noise.

IMPORTANT — THE COMPASS DIRECTION APPROACH:
When the user first requests guidance, show them 4 direction options:
    "Try moving: NORTH | SOUTH | EAST | WEST"
The user picks one and starts walking. After the next scan (10 seconds),
the system checks if RSSI improved. If yes, it confirms the direction.
If no, it tells the user to try a different direction.

This approach is honest — you are not lying about having GPS.
It is the same method professional indoor navigation systems use
when no floor map is available.

import math
import config


# Calibration constant — RSSI measured at exactly 1 metre from the AP.
# Walk to any AP, stand 1 metre away, and note the RSSI value.
# Update this in config.py as:  RSSI_AT_1M = -40
# Default assumption if not calibrated:
RSSI_AT_1M_DEFAULT = -40


def rssi_to_distance(rssi: int, rssi_at_1m: int = None, n: float = None) -> float:
    """
    Convert RSSI (dBm) to estimated distance (metres)
    using the Log-Distance Path Loss model.

    Formula: d = 10 ^ ((RSSI_0 - RSSI) / (10 * n))

    Args:
        rssi        : current measured RSSI in dBm (e.g. -70)
        rssi_at_1m  : RSSI measured at 1 metre from the AP (e.g. -40)
        n           : path loss exponent (2.7 for indoor lab)

    Returns:
        estimated distance in metres (float), minimum 0.5m
    """
    if rssi_at_1m is None:
        rssi_at_1m = getattr(config, 'RSSI_AT_1M', RSSI_AT_1M_DEFAULT)
    if n is None:
        n = getattr(config, 'PATH_LOSS_EXPONENT', 2.7)

    exponent = (rssi_at_1m - rssi) / (10.0 * n)
    distance = math.pow(10, exponent)
    return max(0.5, round(distance, 1))


def get_direction_guidance(
    current_rssi: int,
    previous_rssi: int,
    target_bssid: str = None
) -> str:
    """
    Determines if user is moving closer or further from target AP.
    Uses RSSI delta between the current and previous scan.

    Returns a plain English instruction string.
    """
    delta = current_rssi - previous_rssi
    noise_threshold = 2  # dBm — ignore changes smaller than this (measurement noise)

    # Check if AP has a known position (from config.AP_POSITIONS)
    ap_positions = getattr(config, 'AP_POSITIONS', {})
    known_wall = None
    ap_label = "the target AP"
    if target_bssid and target_bssid in ap_positions:
        info = ap_positions[target_bssid]
        known_wall = info.get("wall")
        ap_label   = info.get("label", "the target AP")

    if known_wall:
        base_direction = f"Move towards the {known_wall.upper()} wall ({ap_label})"
    else:
        base_direction = f"Move towards {ap_label}"

    if delta > noise_threshold:
        return f"Signal improving (+{delta} dBm). Keep going — you are moving CLOSER to {ap_label}."
    elif delta < -noise_threshold:
        return f"Signal weakening ({delta} dBm). TURN AROUND — you are moving FURTHER from {ap_label}. {base_direction}."
    else:
        if known_wall:
            return f"Signal stable. {base_direction}. Try moving LEFT or RIGHT along your current path."
        else:
            return f"Signal stable. Try moving in a different direction to find {ap_label}."


def build_location_message(
    target_bssid: str,
    current_rssi: int,
    previous_rssi: int = None,
    target_ssid: str = ""
) -> str:
    """
    Builds the full location guidance message shown on the dashboard.
    This is the message that looks like:
       "Move LEFT approximately 8 m towards AP-Lab-North..."

    Args:
        target_bssid  : BSSID of the AP the user wants to reach
        current_rssi  : current RSSI of the target AP (dBm)
        previous_rssi : RSSI of target AP from previous scan (for delta)
        target_ssid   : SSID name for display

    Returns:
        Full guidance string for dashboard display.
    """
    distance = rssi_to_distance(current_rssi)

    # Direction part
    if previous_rssi is not None:
        direction_hint = get_direction_guidance(current_rssi, previous_rssi, target_bssid)
    else:
        # First scan — no previous data yet
        direction_hint = "Starting navigation. Begin walking towards the AP."

    # Known wall label
    ap_positions = getattr(config, 'AP_POSITIONS', {})
    ap_label = target_ssid or target_bssid
    wall_hint = ""
    if target_bssid in ap_positions:
        info = ap_positions[target_bssid]
        ap_label  = info.get("label", ap_label)
        known_wall = info.get("wall")
        if known_wall:
            wall_hint = f" (located on the {known_wall.upper()} wall)"

    message = (
        f"Navigation to {ap_label}{wall_hint}: "
        f"Estimated distance = {distance} m | "
        f"Signal = {current_rssi} dBm | "
        f"{direction_hint}"
    )

    return message

PART G — KNOWN LIMITATIONS TO DOCUMENT IN YOUR REPORT
================================================================================

These are honest engineering limitations. You MUST document them in your
final report — your supervisor expects this. It shows engineering maturity.

1. RSSI-to-distance accuracy:
   The Log-Distance model gives an ESTIMATE, not a GPS-precise location.
   Indoor accuracy is typically ±2 to ±5 metres depending on walls and
   interference. This is acceptable for guiding a user to a different wall.

2. Direction without a floor map:
   Without a pre-loaded floor plan, the system cannot say "move LEFT 5 m".
   It can only say "move towards the NORTH wall" if AP_POSITIONS is filled in,
   or give delta-based feedback (closer/further) without a map.

3. OS switching limitations on Windows:
   netsh wlan connect requires the network profile to exist on the device.
   For Eduroam this is usually already saved. For unknown networks it will fail.
   Document this: "The switching feature requires previously-saved network
   credentials. This is appropriate for a university environment where students
   are already authenticated on Eduroam."

4. iOS and browser restrictions:
   This feature only works on the Python desktop app (Windows/Linux laptop).
   Mobile browsers do not allow programmatic WiFi switching. This is a known
   OS security restriction and is correctly excluded from your project scope.

5. RSSI measurement noise:
   WiFi RSSI fluctuates ±3 to ±5 dBm even when standing still.
   The ±2 dBm dead zone in the direction logic accounts for this noise.
   Averaging over multiple scans would improve accuracy further.
